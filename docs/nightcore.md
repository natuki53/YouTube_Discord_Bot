# Nightcore

再生パネルのNightcoreスイッチをオンにすると、1.25倍速で再生し、音程も約3.9半音上がる。オフにすると通常のテンポと音程へ戻る。同じVCの全員へ反映され、曲の切り替え・シークでも設定を引き継ぐ。初期設定はオフ。停止して退出すると設定もリセットされる。

FFmpegの再起動やYouTube音声の再取得はせず、libsoxrの高品質な可変レート変換を使う。切り替えは100msで移行する（初回オン時は直接Nightcore速度へ切り替える）。元の左右の音声を独立して処理し、その後で立体音響を適用する。オフのままなら入力PCMをそのまま通す。過去にあった意図しないテンポ変化とは別に、Discordへ送る48kHz・ステレオ・20msの周期は維持する。

再生バーは元の曲の時間を表示し、Nightcore中は1.25倍の速さで進む。シーク先・配備時の再開位置も元の曲の秒数で扱う。音声末尾は変換器から取り出しきり、最後の短い出力だけ無音で20msへ埋める。バッファーは1つの入力フレームと変換器の内部履歴に限り、音声スレッドのみが所有する。GUI操作は有効フラグを切り替えるだけで音声接続を再起動しない。

右側には総時間ではなく、現在の速度での残り時間をマイナス表記で表示する。計算は `(曲の長さ − 曲内の再生位置) / 現在の速度`。オン・オフの保存結果を受けると直ちに更新し、一時停止中は減らさない。総時間はシークバーの読み上げと残り時間のツールチップで確認できる。

ライブ配信は先の音声を取得できないため、Nightcoreがオンでも通常速度で再生する。次の通常動画ではNightcoreへ戻る。ボタンの説明にもこの制限を表示する。

`PUT /api/guilds/{guild_id}/nightcore` は `{enabled: true/false}` を受け、所属・同じVC・Origin・CSRFを毎回確認する。真偽値以外は拒否する。ブラウザーは保存中の多重送信を防ぎ、古い状態取得でモードや再生速度を巻き戻さない。保存失敗時も操作パネルの配置を保つ。

DockerとCIは `libsoxr0` を明示的に導入する。ネイティブライブラリのない環境ではスイッチを利用不可にし、通常再生を継続する。libsoxrはLGPL-2.1以降で、ライセンスはOSパッケージに含む。API: [SoX Resampler](https://github.com/chirlu/soxr/blob/master/src/soxr.h)。
